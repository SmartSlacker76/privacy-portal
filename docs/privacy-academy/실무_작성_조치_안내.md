# 공공기관 개인정보 실무 주제별 안내

가상 사례 기반 학습자료 · 공식 평가 판정이 아닙니다. 각 지표 원문과 시행일을 함께 확인하세요.

## 조직·책임·내부 관리계획

### 쉬운 설명
책임을 맡을 사람과 승인·보고 절차가 있어야 개선이 실제로 실행됩니다. 문서에 이름만 올리는 것으로 끝내지 않습니다.

### 공공기관 예시
간세다리청 문화정책과는 강좌신청 시스템의 업무책임자, 개인정보 담당자, 운영수탁자의 역할을 구분하고 분기 점검 결과를 보호책임자에게 보고합니다.

### 준비·작성 순서
1. 기관 유형과 보호책임자 자격 요건을 현행 법령으로 확인합니다.
2. 인사발령·업무분장·결재 경로를 연결해 누가 결정하고 누가 수행하는지 적습니다.
3. 올해 계획에 과제별 담당·예산·완료일·산출물을 붙입니다.
4. 회의 결정사항과 실제 개선 결과를 연결합니다.

### 확인 방법
- 공식 지정 문서와 처리방침의 담당자가 일치하는지 대조합니다.
- 계획에만 있고 이행되지 않은 과제가 있는지 확인합니다.

### 증빙
- 보호책임자 지정 문서 및 자격 확인표
- 부서별 역할표와 업무분장
- 내부 관리계획 결재본·점검 결과·조치 완료 보고

### 미흡 시 조치
1. 미지정·공석이면 적격자 지정 절차를 진행하고 공백기간 대행을 정합니다.
2. 업무 누락은 담당자·기한·예산을 배정하고 결과를 재보고합니다.

### 흔한 누락
전년도 계획의 연도만 바꾸고 담당자·실적을 제시하지 않는 경우.

### 자주 묻는 질문
담당자가 바뀌면? 발령일·인수인계일·권한 변경일을 연결하고 홈페이지 안내도 함께 확인합니다.

## 교육·취급자·인적 보안

### 쉬운 설명
같은 교육자료를 배포한 사실보다, 실제 개인정보를 다루는 사람이 필요한 행동을 배웠는지 확인해야 합니다.

### 공공기관 예시
문화강좌 접수 담당자·파견직·유지보수 인력을 포함한 취급자 명부 12명과 교육 이수자 11명을 대조해 미이수자 1명에게 보충교육을 실시했습니다. 숫자는 학습 예시입니다.

### 준비·작성 순서
1. 인사·계정·위탁 명부로 교육 대상자를 확정합니다.
2. 직무별로 접수·조회·출력·오발송 예방 등 교육 내용을 정합니다.
3. 대상자별 일시·내용·이수 여부를 적고 미참석 사유를 확인합니다.
4. 보충교육 및 이해 확인 결과까지 붙입니다.

### 확인 방법
- 대상자 수와 이수자 수의 차이를 설명할 수 있나요?
- 공공시스템 계정 발급 시 교육·서약 요건도 따로 확인했나요?

### 증빙
- 대상자 명부·역할별 교육계획
- 교육자료·출석 또는 수료 확인·보충교육 기록
- 교육 효과 확인표·개선 결과

### 미흡 시 조치
1. 미이수자는 일정을 확정하고 보충교육을 진행합니다.
2. 교육 후 실제 업무 표본을 점검해 반복 오류를 개선합니다.

### 흔한 누락
수료증만 모으고 대상자 전체가 포함되었는지 확인하지 않는 경우.

### 자주 묻는 질문
서약서가 교육을 대신하나요? 목적이 다릅니다. 필요한 교육과 서약을 각각 확인하고 기록합니다.

## 업무·개인정보파일·자산 현황

### 쉬운 설명
무엇을 어디서 처리하는지 알아야 평가대상과 증빙 범위를 정할 수 있습니다. 시스템 외 엑셀·종이·백업·외부연계도 확인합니다.

### 공공기관 예시
강좌신청 DB, 접수창구 종이 신청서, 수탁자의 문자 발송 대기파일을 별도 자산으로 식별했습니다. 각 자산에 업무·보관위치·항목·책임부서·보유 근거를 적었습니다.

### 준비·작성 순서
1. 부서 인터뷰로 처리업무 목록을 작성합니다.
2. 업무별 수집경로·항목·저장소·제공·위탁·파기를 기록합니다.
3. 파일 등록·변경·파기 대상 여부를 검토하고 근거를 적습니다.
4. 실제 화면·DB 목록·계약서와 대조해 누락을 찾습니다.

### 확인 방법
- 인터넷 홈페이지뿐 아니라 내부 파일과 수기대장도 포함했나요?
- 본청·소속기관·위탁업무의 범위가 일치하나요?

### 증빙
- 처리업무 목록·개인정보파일 현황
- 자산대장·데이터 흐름표·변경 이력
- 개인정보파일 등록·변경 검토 기록

### 미흡 시 조치
1. 누락된 자산은 담당자를 지정해 목록에 추가합니다.
2. 실제 운영과 다른 등록·처리방침·흐름도를 함께 정정합니다.

### 흔한 누락
DB 목록만 제출하고 종이 신청서나 위탁업체 보유 자료는 빠진 경우.

### 자주 묻는 질문
개인정보파일과 시스템은 같은가요? 하나의 시스템에 여러 파일이 있을 수 있고 파일이 종이로 존재할 수도 있습니다.

## 수집 근거·최소수집·동의

### 쉬운 설명
공공기관도 모든 개인정보를 자유롭게 수집할 수 있는 것은 아닙니다. 업무 목적별 법적 근거와 필요한 최소 항목을 먼저 확인합니다.

### 공공기관 예시
가상 강좌 신청에서 이름·연락처는 신청 안내 목적에 필요한지 검토하고, 주민등록번호는 단순 본인확인 편의를 이유로 추가하지 않습니다. 홍보 수신 동의는 신청 필수 절차와 구분합니다.

### 준비·작성 순서
1. 처리목적을 구체적인 업무 문장으로 적습니다.
2. 항목별 필요성·법적 근거·필수/선택·보유기간 근거를 표로 씁니다.
3. 동의가 근거라면 고지항목·분리동의·거부 시 영향을 확인합니다.
4. 아동·민감정보·고유식별정보·주민등록번호는 추가 요건을 별도로 검토합니다.

### 확인 방법
- 신청서·온라인 화면·DB 컬럼에서 불필요한 항목을 찾습니다.
- 실제 거부·선택 미체크 상황에서도 불이익 없이 처리되는지 시험합니다.

### 증빙
- 항목별 수집 근거 검토표
- 동의문·신청 화면·개정 전후 비교표
- 선택동의 거부 및 법정대리인 확인 시험 기록

### 미흡 시 조치
1. 불필요 항목의 수집을 중지하고 기존 보유 자료의 파기 또는 적법 보존을 검토합니다.
2. 근거가 불명확하면 법무·업무부서 검토 후 양식·화면·안내문을 함께 수정합니다.

### 흔한 누락
관련법에 따라 수집이라고만 쓰고 실제 근거 조항과 항목 필요성을 제시하지 않는 경우.

### 자주 묻는 질문
공공업무면 동의가 항상 필요한가요? 업무·목적에 적용되는 법정 근거가 있는지 먼저 판단하고, 동의가 근거인 처리에는 적법한 동의 절차를 적용합니다.

## 이용·제3자 제공·국외이전

### 쉬운 설명
수집할 수 있었다고 해서 다른 기관에 제공할 수 있는 것은 아닙니다. 받는 쪽의 목적·권한·항목을 함께 검토합니다.

### 공공기관 예시
가상 타 기관의 수강 이력 요청은 공문이 있다는 이유만으로 승인하지 않습니다. 제공 근거·필요 항목·대상 기간을 검토하고 최소 자료만 안전한 경로로 전달합니다.

### 준비·작성 순서
1. 요청기관·목적·대상·항목·기간·법적 근거를 접수합니다.
2. 목적 내/외 이용과 제3자 제공 여부를 구분합니다.
3. 승인·필요한 고지·공개·보호조치 및 제공대장 사항을 확인합니다.
4. 전달 일시·수신 확인·수신기관 관리조건을 기록합니다.

### 확인 방법
- 위탁과 제3자 제공을 이름만으로 구분하지 않았나요?
- 국외 저장·접근·재위탁 여부도 실제 서비스 구조로 확인했나요?

### 증빙
- 이용·제공 검토서 및 승인
- 제공대장·송수신 확인·보호조치 요청
- 국외이전 요건 검토표(해당 시)

### 미흡 시 조치
1. 근거 없는 제공은 중지하고 이미 전달된 자료의 사용중지·회수·삭제 등 필요한 조치를 검토합니다.
2. 제공 범위를 축소하고 승인·전송·확인 절차를 보완합니다.

### 흔한 누락
협조 공문이나 MOU만으로 모든 제공이 가능하다고 판단하는 경우.

### 자주 묻는 질문
같은 시청의 다른 부서면 무조건 괜찮나요? 처리목적·업무상 필요·권한을 확인하며 내부 이동도 이용 범위를 검토합니다.

## 위탁·재위탁·수탁자 감독

### 쉬운 설명
기관 대신 처리하는 업무라도 기관의 관리·감독 책임이 사라지지 않습니다. 계약→접근권한→점검→종료까지 연결합니다.

### 공공기관 예시
문자 발송 수탁자에게 연락처와 발송문만 전달합니다. 계약서에 목적 외 처리 금지·안전조치·재위탁·반환/파기 등을 반영하고 종료 시 남은 대기파일 삭제를 확인합니다.

### 준비·작성 순서
1. 수탁업무·업체·처리항목·보관장소·재위탁을 조사합니다.
2. 계약 필수사항과 공개·고지 필요사항을 확인합니다.
3. 점검 항목별 요구자료와 현장 확인 방법을 정합니다.
4. 개선요청·완료확인·계약 종료 시 반환/파기를 추적합니다.

### 확인 방법
- 수탁자 자체 점검표만 받고 원자료를 확인하지 않았나요?
- 재위탁 업체와 클라우드 저장 위치가 현황에 포함됐나요?

### 증빙
- 수탁업무 현황·계약 조항 대조표
- 교육·점검 결과·개선요청 및 재점검
- 종료 확인서·반환/파기 검증 기록

### 미흡 시 조치
1. 계약 누락은 적법한 변경 절차로 보완하고 접근범위를 즉시 최소화합니다.
2. 미이행 사항은 담당·기한을 정해 재점검하고 계약상 대응을 검토합니다.

### 흔한 누락
계약서만 있고 실제 감독·종료 후 삭제 확인은 없는 경우.

### 자주 묻는 질문
수탁자 점검표에 모두 양호면 충분한가요? 표본 근거·화면·로그·인터뷰로 진위를 확인하고 그 확인 방법을 남깁니다.

## 처리방침·정보주체 권리

### 쉬운 설명
정보주체가 어디로 어떻게 요청하고 어떤 답을 받는지 쉽게 알 수 있어야 합니다. 접수 경로만 있고 실제 처리가 안 되면 부족합니다.

### 공공기관 예시
가상 시민의 본인 강좌 신청내역 열람 요구를 접수하고 신원을 확인한 뒤 조회 범위·제3자 정보 포함 여부·법정 처리기한을 검토해 통지했습니다.

### 준비·작성 순서
1. 온라인·방문 등 접수 경로와 담당자를 공개합니다.
2. 본인·대리인 확인에 필요한 최소 자료를 정합니다.
3. 요구 유형별 기한·제한 사유·통지·이의 절차를 확인합니다.
4. 접수부터 회신까지 날짜와 처리 근거를 대장에 남깁니다.

### 확인 방법
- 처리방침이 실제 수집·제공·위탁 현황과 맞나요?
- 테스트 민원을 넣었을 때 담당부서까지 전달되나요?

### 증빙
- 처리방침 변경 비교·게시 이력
- 권리행사 접수·검토·통지 대장
- 본인확인 절차·이의신청 안내

### 미흡 시 조치
1. 지연·누락을 확인하면 처리상태를 알리고 필요한 조치를 이행합니다.
2. 오래된 연락처·위탁 목록·처리방침을 실제 운영과 함께 정비합니다.

### 흔한 누락
처리방침 샘플을 복사해 실제 없는 수탁자나 잘못된 보유기간을 게시하는 경우.

### 자주 묻는 질문
교육용 대장에 실제 주민 이름을 넣어도 되나요? 이 실습에서는 가상정보만 사용하고 실제 증빙을 공유할 때도 불필요한 개인정보를 가립니다.

## 계정·최소권한·인사 연계

### 쉬운 설명
업무에 필요한 사람만 필요한 범위에 접근하도록 하고 인사 변경 즉시 권한을 다시 확인합니다.

### 공공기관 예시
가상 직원의 전보 발령 09:00 → 업무부서 통보 09:10 → 기존 시스템 권한 말소 09:20 → 접근 거부 확인 09:25를 요청·승인·처리 기록으로 연결합니다.

### 준비·작성 순서
1. 시스템별 역할과 허용 기능을 표로 정의합니다.
2. 계정 신청에 업무사유·권한·만료·승인자를 기재합니다.
3. 인사자료와 계정·권한 목록을 대조합니다.
4. 부여·변경·말소 기록과 접근시험 결과를 남깁니다.

### 확인 방법
- 공용계정·퇴직자·장기 미사용·과도한 관리자 권한이 있나요?
- 공공시스템 해당 시 인사 연계·교육·서약·정기 점검 추가 요건을 확인했나요?

### 증빙
- 역할별 권한표·인사 대조표
- 권한 신청·승인·변경·말소 이력
- 설정 화면·비인가 접근 차단 시험

### 미흡 시 조치
1. 불필요 계정은 정지·회수하고 업무에 필요한 최소권한으로 변경합니다.
2. 원격접속은 승인된 경로와 인증수단으로 제한하고 차단 결과를 확인합니다.

### 흔한 누락
계정 목록만 있고 승인사유·전보 후 회수 이력은 없는 경우.

### 자주 묻는 질문
비밀번호만 바꾸면 해결되나요? 불필요한 접근권한과 계정 자체를 회수해야 하며 접근통제·로그까지 함께 확인합니다.

## 접속기록·이상행위·다운로드 소명

### 쉬운 설명
누가 언제 누구의 정보를 어떤 작업으로 처리했는지 추적하고 이상한 사용을 실제로 확인해야 합니다.

### 공공기관 예시
가상 10월 점검에서 담당자 A의 대량 조회를 발견했습니다. 업무 승인과 조회 대상 범위를 대조해 사유를 확인하고 과다 권한 1건을 축소한 뒤 재조회 차단을 검증했습니다.

### 준비·작성 순서
1. 기록 항목과 대상 시스템·보관기간 적용 근거를 정합니다.
2. 원본 로그에서 필수 항목과 누락 구간을 표본 확인합니다.
3. 기관 기준에 따라 대량조회·다운로드·업무 외 접속 등을 분석합니다.
4. 발견→소명→판단→조치→재점검을 사건번호로 연결합니다.

### 확인 방법
- 수집 사실만 있고 실제 점검 결과는 없나요?
- 기록 위변조 방지·접근 제한·백업·보관기간도 확인했나요?

### 증빙
- 접속기록 항목 정의서·가상 표본
- 점검 보고서·다운로드 사유 확인서
- 이상행위 조치 및 재점검 기록

### 미흡 시 조치
1. 누락 필드는 프로그램·설정을 보완하고 정상 기록을 재확인합니다.
2. 의심 행위는 담당부서 확인 및 사고 대응 절차에 따라 조사하고 계정을 통제합니다.

### 흔한 누락
로그 캡처 한 장으로 월별 점검·소명까지 완료했다고 주장하는 경우.

### 자주 묻는 질문
로그 보관기간은 모두 같나요? 처리규모·정보유형·공공시스템 여부 등 적용 조건을 현행 기준 제8조·제17조와 대조합니다. 예시 기간을 그대로 복사하지 않습니다.

## 암호화·키·안전한 전송

### 쉬운 설명
전송구간 암호화, 저장 데이터 암호화, 비밀번호 보호는 서로 다른 확인 대상입니다. HTTPS 화면만으로 저장 암호화를 입증하지 못합니다.

### 공공기관 예시
강좌 신청 웹 구간 TLS, 내부 API 전송, DB 저장 필드, 백업 파일을 각각 확인합니다. 비밀번호는 복원 가능한 일반 암호화와 구분해 안전한 단방향 처리 여부를 검토합니다.

### 준비·작성 순서
1. 정보유형과 저장·전송 위치를 표로 나눕니다.
2. 암호화 대상·예외 조건·위험도 분석 필요 여부를 현행 기준과 대조합니다.
3. 알고리즘·프로토콜·키 접근권한·교체·백업 절차를 확인합니다.
4. 테스트 데이터로 전송과 저장 상태를 구분해 검증합니다.

### 확인 방법
- 내부 연계·배치·백업·매체도 검토했나요?
- 키를 암호문 옆에 동일 권한으로 두지 않았나요?

### 증빙
- 암호화 적용 구간·필드 목록
- 설정 확인·테스트 결과·키 권한표
- 개선 전후 비교 및 복구시험

### 미흡 시 조치
1. 평문 구간을 차단하거나 안전한 전송으로 전환합니다.
2. 저장 암호화와 키 관리 변경은 영향 검토·백업·복구시험 후 적용합니다.

### 흔한 누락
브라우저 자물쇠만으로 DB·다운로드 파일까지 안전하다고 판단하는 경우.

### 자주 묻는 질문
암호화했으면 외부에 공개해도 되나요? 암호화와 별개로 적법한 처리 근거·접근권한·보관과 파기 의무가 유지됩니다.

## 취약점·개발·API·악성코드

### 쉬운 설명
점검 보고서의 취약점 수보다 실제 개선과 재발 방지가 중요합니다. 공개 웹 외 API·관리화면·수탁자 연결도 확인합니다.

### 공공기관 예시
가상 신청 API에서 다른 신청번호의 연락처가 조회되는 결함을 발견했습니다. 서버에서 소유자 권한을 검증하도록 수정하고 다른 계정의 재현시험으로 차단을 확인했습니다.

### 준비·작성 순서
1. 자산·서비스·API·공급망 연계 범위를 확정합니다.
2. 승인받은 점검 계획에 시간·범위·영향·복구·연락망을 적습니다.
3. 발견 항목에 재현조건·영향·우선순위·증빙을 기록합니다.
4. 수정 버전·배포일·재점검·잔여 위험 승인까지 연결합니다.

### 확인 방법
- 패치 설치 여부와 서비스 정상 동작을 함께 확인했나요?
- 공공시스템 제18조의 2027년 시행 준비를 별도 일정에 넣었나요?

### 증빙
- 점검 계획·대상 목록·진단 결과
- 조치대장·변경 승인·패치 이력
- 재점검 및 잔여위험 관리

### 미흡 시 조치
1. 긴급 노출은 접근 차단 등 임시조치를 먼저 적용합니다.
2. 원인 수정·패치 후 승인된 재점검으로 해결 여부를 확인합니다.

### 흔한 누락
자동 스캔 결과만 제출하고 권한검증·업무로직 결함과 개선 확인은 없는 경우.

### 자주 묻는 질문
침투테스트는 아무 시스템에 실행해도 되나요? 사전에 승인된 범위·기간·중단조건에서만 수행하며, 이 사이트는 가상 데이터 학습만 제공합니다.

## 물리 보안·출력·매체·복구

### 쉬운 설명
서버 설정이 안전해도 열린 캐비닛·방치된 출력물·반출 매체로 유출될 수 있습니다.

### 공공기관 예시
가상 문화정책과가 종이 신청서 캐비닛 잠금과 열쇠 관리자, 출력물 회수, 수탁자 전산실 출입, 백업 복구시험을 구분해 점검했습니다.

### 준비·작성 순서
1. 장소·서류·출력장치·매체·백업 목록을 작성합니다.
2. 출입·반출·출력 승인자와 점검 주기를 정합니다.
3. 표본을 정해 현장 상태·대장·실제 보관을 대조합니다.
4. 복구시험의 목표·대상·결과·미흡사항을 기록합니다.

### 확인 방법
- 출입대장에 동행자·입퇴실 시각·목적이 있나요?
- 백업 성공과 실제 복구 성공을 구분했나요?

### 증빙
- 출입·매체 반출입 대장
- 잠금·출력 통제 점검표
- 백업 정책·복구시험 결과

### 미흡 시 조치
1. 방치 자료를 통제된 장소로 이동하고 권한·잠금·회수 절차를 보완합니다.
2. 복구 실패는 원인을 조치하고 재시험 결과를 승인받습니다.

### 흔한 누락
캐비닛 사진만 있고 관리책임자·열쇠 통제·점검 이력이 없는 경우.

### 자주 묻는 질문
사진은 꼭 필요한가요? 지표에 필요한 사실을 입증할 수 있는 자료를 선택하고 사진의 개인정보·내부 보안정보 노출을 최소화합니다.

## 보유기간·파기·분리 보관

### 쉬운 설명
업무가 끝난 자료를 계속 보관하려면 별도의 적법한 이유가 있는지 확인해야 합니다. 파기대장만 쓰고 실제 데이터가 남으면 부족합니다.

### 공공기관 예시
가상 강좌가 종료되면 보유 근거표에 따라 파기대상을 추출하고 DB·첨부파일·담당자 PC·수탁자 복사본을 확인합니다. 다른 법률상 보존대상은 근거와 접근 제한을 별도로 기록합니다.

### 준비·작성 순서
1. 항목·업무별 보유기간 및 법정 보존 근거를 확인합니다.
2. 파기대상 선정일·수량·저장위치·승인자를 적습니다.
3. 복구 불가능한 방법을 대상 매체에 맞게 적용합니다.
4. 삭제 결과·잔존자료 확인·수탁자 확인을 남깁니다.

### 확인 방법
- 운영 DB 외 임시파일·다운로드·종이·백업 정책을 검토했나요?
- 기록물법상 보존 등 다른 법률과 충돌하지 않도록 검토했나요?

### 증빙
- 보유 근거표·파기대상 목록
- 파기 승인·실행·검증 보고
- 분리 보관 및 수탁자 파기 확인

### 미흡 시 조치
1. 근거 없는 장기보유는 승인 후 적정 파기합니다.
2. 분리보존은 대상·근거·기간·접근권한·종료 후 파기를 관리합니다.

### 흔한 누락
위탁업체 파기확인서를 받았지만 기관 PC의 내려받은 파일은 남아 있는 경우.

### 자주 묻는 질문
예시 보유기간을 그대로 써도 되나요? 안 됩니다. 업무별 법령·목적을 검토해 정해야 하며 이 실습의 일정은 법정 보유기간이 아닙니다.

## 유출·침해 대응·재발 방지

### 쉬운 설명
초동조치·사실 확인·통지/신고 판단·복구·재발 방지를 시간순으로 기록해야 나중에 적절성을 설명할 수 있습니다.

### 공공기관 예시
가상 파일 오발송 발견 09:00 → 추가발송 중지 09:05 → 수신자 회수 요청 → 노출 항목·대상·열람 여부 확인 → 법정 통지/신고 요건 검토 → 원인 개선과 효과 확인으로 진행합니다.

### 준비·작성 순서
1. 발견·인지 시각과 확인된 사실/미확인 사실을 구분합니다.
2. 확산 방지와 증거 보존을 병행하고 책임자에게 보고합니다.
3. 현행 통지·신고 대상·기한·항목을 확인해 판단 근거를 기록합니다.
4. 피해 최소화·원인 분석·복구·재발 방지·재점검을 문서화합니다.

### 확인 방법
- 사고를 늦게 알게 된 경위와 실제 인지 시각을 구분했나요?
- 조치 로그·통지문·신고 접수증과 보고서 시각이 맞나요?

### 증빙
- 사고 시간대별 대응일지
- 범위·원인 분석·통지/신고 판단 및 실행 자료
- 사건별 재발방지 계획·이행·효과 확인

### 미흡 시 조치
1. 노출 경로를 통제하고 계정·토큰 등을 필요에 따라 회수합니다.
2. 관리적·기술적 원인을 함께 고치고 반복 방지 효과를 재점검합니다.

### 흔한 누락
일반 사고대응 매뉴얼을 특정 사고의 재발방지 실적으로 제출하는 경우.

### 자주 묻는 질문
확인 전에도 기록하나요? 확인된 사실과 추정·미확인 항목을 분리해 기록하고 조사에 따라 갱신합니다.

## 영향평가·위험 분석·개선 추적

### 쉬운 설명
시스템 설계가 끝난 뒤 체크리스트만 채우는 것이 아니라 실제 처리 흐름에서 위험을 찾아 설계·운영 개선으로 연결합니다.

### 공공기관 예시
FLOW-03 문자발송 → 전화번호 외 강좌 상세가 불필요하게 전달되는 위험 R-03 → 관련 영향평가 지표 연결 → 발송 항목 축소 → 송신 로그와 수탁자 수신 파일을 재확인합니다.

### 준비·작성 순서
1. 법정 대상 여부·추진 일정·수행 주체를 검토합니다.
2. 흐름도·구조도·보호조치 목록을 작성합니다.
3. 각 지표별 문서·인터뷰·현장 점검의 판단 근거를 남깁니다.
4. 위험별 개선 책임·기한·완료 증빙·재점검·제출 이력을 추적합니다.

### 확인 방법
- 흐름 ID·위험 ID·지표번호·증빙 ID가 연결되나요?
- 해당없음에는 사실관계와 적용 제외 이유를 남겼나요?

### 증빙
- 대상 여부 검토서·평가 계획
- 총괄/업무별 흐름도·구조도·보호조치 목록
- 지표별 진단·위험 분석·개선 이행 및 제출 자료

### 미흡 시 조치
1. 흐름도와 다른 실제 운영을 먼저 현행화합니다.
2. 개선계획을 설계·계약·개발·운영에 반영하고 결과를 검증합니다.

### 흔한 누락
모든 지표에 양호를 선택했지만 확인 자료나 실제 인터뷰 결과가 없는 경우.

### 자주 묻는 질문
학습 점수가 평가점수인가요? 아닙니다. 여기의 점수는 작성 누락을 줄이는 연습용이며 법적 적합성·공식 등급을 판정하지 않습니다.

## 고정형·이동형 영상정보

### 쉬운 설명
고정형과 이동형의 적용 기준을 구분하고 설치·촬영·열람·제공·파기 전 과정에서 목적과 권리를 확인합니다.

### 공공기관 예시
가상 민원실 CCTV의 설치 근거·안내판·운영방침·위탁 감독·열람 처리·파기 기록을 한 묶음으로 대조합니다. 타인이 함께 촬영된 영상은 권리 침해를 검토합니다.

### 준비·작성 순서
1. 장치 유형·설치/촬영 목적·범위·보관장소를 확인합니다.
2. 운영방침·알림·접근권한·위탁 현황을 점검합니다.
3. 열람·제공 요청의 본인·대리인·법적 근거와 최소 범위를 검토합니다.
4. 처리 결과·제공·파기 내역을 관리대장에 기록합니다.

### 확인 방법
- 실제 촬영범위와 안내판·방침이 일치하나요?
- 요청 공문만으로 제한 없이 제공하지 않았나요?

### 증빙
- 기기 현황·설치 근거·운영방침
- 안내판·접근권한·위탁 감독 기록
- 열람·제공 검토 및 영상 관리대장

### 미흡 시 조치
1. 부적절 촬영 범위·열람권한을 조정합니다.
2. 안내·대장·위탁 감독 누락을 보완하고 재점검합니다.

### 흔한 누락
운영방침은 있지만 실제 열람·외부 제공 기록이 없는 경우.

### 자주 묻는 질문
이동형도 고정형과 같나요? 적용 요건·알림 방식 등이 다르므로 장치와 촬영 상황에 맞는 조항을 따로 확인합니다.

## 가명정보·AI·신기술

### 쉬운 설명
공개되었거나 기술적으로 이용 가능하다고 해서 제한 없이 개인정보를 쓸 수 있는 것은 아닙니다. 목적·근거·재식별·학습 및 저장 경로를 확인합니다.

### 공공기관 예시
가상 민원요약 AI 실험은 실제 민원인의 식별정보를 외부 도구에 입력하는 대신 가상 문서로 검증합니다. 운영 도입 전 처리근거·위탁/이전·학습사용·출력 노출·접근권한을 검토합니다.

### 준비·작성 순서
1. 입력·학습·검색·출력·로그·삭제 흐름을 그립니다.
2. 처리 근거·목적 적합성·정보주체 권리·재식별 위험을 검토합니다.
3. 공급자·국외이전·보관·재학습 조건을 확인합니다.
4. 시험 결과·위험·조치·잔여위험 승인과 운영 모니터링을 기록합니다.

### 확인 방법
- 가명정보와 익명정보를 혼동하지 않았나요?
- 모델 출력·검색 색인·프롬프트 로그에도 정보가 남나요?

### 증빙
- 신기술 개인정보 검토서
- 데이터 흐름·계약/설정 검토·시험 결과
- 위험 개선 및 운영 모니터링 기록

### 미흡 시 조치
1. 불필요한 실제 정보 입력을 중지하고 최소화·가림·권한 통제를 적용합니다.
2. 재식별·출력 유출 위험을 다시 시험하고 목적 외 사용을 제한합니다.

### 흔한 누락
가명처리했으므로 개인정보 법령이 전혀 적용되지 않는다고 판단하는 경우.

### 자주 묻는 질문
생성형 AI가 증빙을 써주면 그대로 제출해도 되나요? 실제 사실·수치·근거·승인과 일치하는지 사람이 검증해야 합니다.
