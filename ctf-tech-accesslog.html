privacy_access.log — 접속기록 점검
[접속일시] 누가 ‘언제’ 접근했나 — 심야·업무시간 외가 적신호
acct= 계정(식별자) — 임시·공용·퇴직자 계정 주의
ip= 접속지 IP — 내부망(10.x) 밖 외부 IP 주의
menu/action 수행업무 — VIEW·UPDATE는 소량, EXPORT·다운로드·출력이 핵심
target / count 처리한 정보주체·건수 — 대량(count)이면 유출 규모
result / 🚨경보 처리결과·자동 경보 — 임계 초과 시 자동 알림
로그 보는 법 4단계
  1. 기준선(정상) 파악: 업무시간대·1건 단위·내부 IP의 평범한 조회가 ‘정상’이에요.
  2. 이탈 찾기: 시간(심야)·계정(임시)·IP(외부)·행위(EXPORT)·건수(대량)가 기준에서 벗어난 줄을 찾아요.
  3. 경보 확인: 🚨·Alert·Unauthorized 같은 자동 경보 표식을 따라가요.
  4. 흔적 수집: 공격자가 남긴 파라미터·피드백·게시글(평문)에서 FLAG 같은 결정적 단서를 확보해요.
⚠ 함정 주의 문제와 무관한 ‘DDoS·웹셸 Write-up 예시’ 같은 디코이 설명에 현혹되지 마세요. 단서는 EXPORT·count·🚨경보·text=FLAG 뿐이에요.

⚖ 해당 법령 · 지침 · 안내서

  • 개인정보 보호법 제29조(안전조치 의무) → 「개인정보의 안전성 확보조치 기준」(고시) 제8조: 접속기록 최소 1년(민감·고유식별정보·100만 명 이상·공공시스템은 2년) 보관, 월 1회 이상 점검이 법정 최소 기준이며, 본 기관은 이를 강화해 매일(일일) 점검을 수행. 특히 개인정보를 다운로드한 경우 그 사유를 반드시 확인.
  • 제16조(공공시스템운영기관 특례): 접속기록을 자동화된 방식으로 분석해 이상행위(업무시간 외·대량·미인가 IP)를 탐지.
  • 표준 개인정보 보호지침 및 개인정보의 안전성 확보조치 기준 해설서: 접속기록 필수 기록항목·점검 방법 안내.
  • 개인정보 보호법 제34조: 유출 시 정보주체 통지·일정 규모 이상 72시간 내 신고(보호위/KISA).
